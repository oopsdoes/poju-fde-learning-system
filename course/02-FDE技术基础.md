# 02｜技术基础：命令行、Git、Python、HTTP、JSON、API

## 学习目标

能定位文件、运行脚本、记录错误、保存版本、处理 JSON、理解 HTTP 请求与响应，并调用安全的只读 API 保存证据。

## 知识点

- 命令行：定位、运行、观察和复现；
- Git：状态、差异、提交和版本证据；
- Python：读取、过滤、排序和输出结构化数据；
- HTTP：方法、状态码、请求、响应和认证；
- JSON：对象、数组和字段；
- API：文档、参数、限制和错误处理。

## 白话解释

命令行是操作台，Git 是操作记录，Python 是处理工具，HTTP 是传输方式，JSON 是数据盒子，API 是点单窗口。FDE 不需要先成为后端专家，但必须能知道哪里出错、如何复现和如何交接。

## 思维导图

```text
技术基础
├─ 命令行：找到、运行、观察
├─ Git：记录、比较、恢复
├─ Python：读取、转换、输出
├─ HTTP/JSON/API：请求、数据、接口
└─ 可靠性：日志、凭据、复现、人工判断
```

## 练习任务

1. 记录 Python、Git、Node 版本，列出项目文件并保存输出。
2. 用 Python 读取脱敏招投标示例 JSON，筛选、排序并输出 Markdown。
3. 调用一个无需敏感凭据的只读 API，记录 URL、方法、状态码、字段和错误。
4. 用 Git 保存至少两次有意义的提交和一次差异说明。

## 作业产物

建立一个包含 `README.md`、`input.json`、`process.py`、`output.md`、`api-notes.md`、`git-log.txt` 和 `errors.md` 的技术练习目录。

## 验收标准

- 按 README 可复现；
- 不硬编码密钥和个人路径；
- JSON 字段缺失时不静默下结论；
- API 记录请求、响应和状态码；
- Git 至少两次有意义提交；
- 输出明确是辅助整理，不是最终资格判断。

## 常见错误

- 只复制命令，不知道当前目录和输入输出；
- 看到 HTTP 200 就认为业务成功；
- 把密钥写进脚本或 Git；
- 改原始资料而不留版本；
- 用一次成功证明可靠。
