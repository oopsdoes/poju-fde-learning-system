# FDE 视频认知模块｜第一批

> 资料状态：已蒸馏的公开课程补充，未代表学习者已掌握。
> 来源类型：本地 FDE 视频资料的筛选与方法蒸馏 + 课程设计补充。
> 公开边界：不包含原始视频、完整转写、私人路径、处理日志、账号信息或未核实宣传数字。

## 用途

本模块为课程 01、02、03、04、07、09 提供认知补充。它把视频资料转成可学习的方法框架，不要求学习者逐条观看视频，也不把资料入库当成学习完成。

## 一、FDE 的工作定义

FDE 是把产品或技术能力嵌入客户真实工作流程，并推动问题定义、部署使用和可验证结果的复合型交付角色。FDE 可以在小团队中兼任售前、开发、培训或项目协调，但必须明确输入、责任、输出、人工确认和验收人。

## 二、Demo 不等于交付

一个能聊天、生成内容或调用工具的 Demo，只证明某个技术动作可能跑通。交付还要回答：

- 谁在什么流程中使用；
- 输入从哪里来，输出交给谁；
- 哪些动作由系统完成，哪些由人确认；
- 出错后谁发现、谁处理；
- 用什么产物或指标证明有效。

## 三、需求要落到真实流程

从角色、目标、实际步骤、使用的资料和系统、卡点、例外、结果开始观察，不把“用户说想要一个 Agent”直接当成需求。先确定正确问题，再决定是否需要检索、工作流、工具调用或其他技术。

## 四、技术是手段

| 技术 | 可以帮助解决 | 不能自动证明 |
|---|---|---|
| RAG/向量检索 | 让回答参考指定资料 | 资料质量、权限和答案可靠性 |
| Agent/工具调用 | 按条件调用工具或接口 | 业务流程正确、风险可控、可以上线 |
| API 服务层 | 让能力被其他系统调用 | 安全、稳定、可维护 |
| Workflow/Skill | 固化步骤、角色和输入输出 | 可以替代审批或异常处理 |

技术选择必须考虑数据、成本、延迟、权限、内网、维护和用户采用。具体版本、参数、端口、价格和云服务配置必须以当前官方文档或实测环境为准。

## 五、受控交付闭环

```text
问题定义 → 范围确认 → 方案草图 → 最小实现 → 用户试用
→ 人工确认 → 异常记录 → 验收 → 复盘与复制
```

涉及资格、报价、合同、盖章、提交或法律合规的动作，不得默认交给自动流程。系统可以整理、标记、生成草稿和提示待确认项，但必须保留授权人员的判断和审核。

## 六、能力表达与宣传边界

面试或作品说明应围绕：

```text
场景/问题 → 约束 → 判断 → 方案与取舍 → 结果/证据 → 复盘
```

课程案例只能作为练习素材，不能写成个人经历。薪资、就业率、行业规模、课程承诺和“学完即就业”等说法必须单独核实，不能作为能力结论。

## 七、练习入口

- 用自己的话写一段 FDE 定义，并列出三个相邻角色边界；
- 把一个 Demo 改写成“用户、输入、输出、人工确认、异常、验收”的交付说明；
- 选择贯穿项目的一步，画出系统辅助与人工审核的边界。

## 八、来源与状态

本模块依据本地视频资料的第一批学习卡和项目课程设计整理。原始证据、时间戳和待核对项保留在私有资料区；公开版本只保留经压缩的通用方法框架。资料已入库，学习者仍需通过课程讲解、测验、练习和验收建立自己的能力证据。
